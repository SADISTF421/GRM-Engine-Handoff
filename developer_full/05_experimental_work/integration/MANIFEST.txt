GRM OGSR ENGINE SAVE INTEGRATION — ЧАСТИЧНАЯ ЭКСПЕРИМЕНТАЛЬНАЯ ПОСТАВКА

ВАЖНО: в этом архиве НЕТ исправленной DLL. Это НЕ системная защита сохранений.
Только скриптовый эксперимент против конфликта разделки и независимый C++
прототип проверки границ. В игре не проверено. Краш не локализован.

INSTALL: три скрипта из V3.3, совместимые с известной базой V3.2.
- grm_gore_test.script: wpn_knife исключён из логики отрыва; временные
  отметки и запланированное скрытие сбрасываются при начале разделки.
- xr_motivator.script: игрок с wpn_knife не запускает отдельный обработчик
  shiza_gore_on_hit; прочие обработчики удара остаются. Проверка касается
  именно активного ножа игрока, не произвольного оружия NPC.
- shiza_reznya.script: очистка записи gore в начале и перед release;
  существующий sl_rotting.forget получает объект, как ожидает его API;
  отложенный обработчик перепроверяет ALife ID, online и имя/секцию. Если
  цель не прошла проверку, разделка отменяется и управление возвращается.
  Позиция создания тела берётся из obj:position(), не из кости головы.
  Очистка скриптовой записи НЕ снимает движковые render/physics hooks.

НЕ РЕАЛИЗОВАНО: xrGame/xrCore исправления, проверка обоих этапов save,
атомарная запись, ротация .sav, ограничение/санация pstor, диагностика 7000,
проверка порядка физики и костей. Прототип SOURCE/packet_guard.h никак не
подключён к игре и не обеспечивает защиту сохранений. Он не является DLL.
Переполнение не должно приводить к тихому пропуску произвольного чанка:
это может сохранить неполные квесты и сломать последовательность загрузки.

Нет оснований считать накопление 8192 неизбежным или объявлять причиной
вылета предупреждение об OGG, обработку костей либо конкретный механизм кучи.
Адрес без достоверной базы загрузки, соответствующего PDB и машинного кода
не устанавливает функцию или причину. Ошибки движка pcall не перехватывает.
Результаты V3.2 — успешная короткая игровая проверка, не гарантия долгой игры.

ИСТОЧНИКИ И ОГРАНИЧЕНИЯ ДВИЖКА
Исследовательская версия исходников из комплекта не подтверждена как исходник
фактически установленной GRM DLL. PDB совпадает по GUID, но DLL age 22,
PDB age 1. Отсутствует совместимая подтверждённая Win32 сборочная среда,
проект и проверка ABI. Сборка DLL из несоответствующих исходников опасна.
В имеющемся коде CALifeObjectRegistry уже использует can_save(), поэтому
проверки online/DirectDamage без знания смысла могут пропустить важные NPC.
В исследовательском NET_utils.h строгая проверка count < 8192; 8192 — размер
массива, а не подтверждение, что 8192 байта можно безопасно записывать.

Проверенный код OGSR main:
https://github.com/OGSR/OGSR-Engine/blob/main/ogsr_engine/xrGame/alife_storage_manager.cpp
https://github.com/OGSR/OGSR-Engine/blob/main/ogsr_engine/xrGame/alife_object_registry.cpp
На момент просмотра storage manager OGSR пишет через FS.w_open целевого пути;
указанная в запросе атомарная транзакция в этом фрагменте не подтверждена.
Публичная текущая инструкция OGSR предусматривает x64, не является готовой
заменой для вашей 32-битной GRM:
https://github.com/OGSR/OGSR-Engine

УСТАНОВКА
1. Закрыть игру. Сделать полный бэкап игры и отдельную копию всех сейвов.
2. Перед заменой проверить SHA-256 трёх фактических файлов. В PowerShell:
   Get-FileHash -Algorithm SHA256 'путь\gamedata\scripts\ИМЯ.script'
3. Установить только при совпадении всех трёх хэшей V3.2 ниже; если они
   совпадают с указанными хэшами V3.3 — эти файлы уже установлены.
   При иных хэшах не устанавливать поверх пользовательских изменений.
4. Скопировать gamedata из INSTALL в корень игры. Проверить сначала на копии
   сохранения: обычный и обезглавленный труп, нож, разделка, F5/F9, переход.
   Если разделка отменяется, это отдельный непроверенный риск API server.online.
   demo_record, свободную камеру и NumPad 5 при тесте не использовать.
